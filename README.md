# مُريح (MUREEH) — الموقع + لوحة التحكم

## البنية التقنية الحالية

- **قاعدة البيانات:** PostgreSQL عبر Supabase (لم تعد SQLite محلية).
- **تخزين الصور:** Supabase Storage (bucket عام) بدلاً من القرص المحلي — ضروري لأن استضافات مثل Render تمسح القرص المحلي مع كل نشر جديد.
- **الاستضافة المستهدفة:** Render (كخدمة Node واحدة، عبر `render.yaml` — مُتحقَّق منه مقابل مخطط Render الرسمي، Node 22 مُثبَّت صراحةً لأن Node 20 انتهى دعمه في أبريل 2026).
- **المصادقة:** رمز JWT مخزّن في `localStorage` (وليس كوكيز جلسة) — يعمل بشكل موثوق حتى عند عرض لوحة التحكم داخل إطار iframe من نطاق مختلف (كما في معاينات الاستضافة السحابية).

## التشغيل محليًا

```bash
cd server
cp .env.example .env
# عدّل .env: ضع رابط اتصال Postgres حقيقي (Supabase أو محلي)، راجع server/README.md بالتفصيل
npm install
npm run dev
```

سيعمل كل شيء على منفذ واحد: **http://localhost:4000**
- الموقع العام: `/`
- لوحة التحكم / تسجيل الأعضاء: `/admin`
- الـ API: `/api/*`
- فحص الصحة (لـ Render): `/healthz`

## الإعداد الكامل لـ Supabase + النشر على Render

راجع **`server/README.md`** للدليل الكامل خطوة بخطوة: إنشاء مشروع Supabase، الحصول على رابط قاعدة البيانات، إنشاء bucket لتخزين الصور، ونشر الموقع على Render (عبر `render.yaml` الجاهز في جذر المشروع).

## نظام الأعضاء وسير الموافقة

- أي زائر يمكنه إنشاء **حساب عضو** من تبويب "عضو جديد" في `/admin`.
- **المسؤول (Admin):** يرى كل المشاريع، ينشرها فورًا، ويوافق/يرفض مشاريع الأعضاء، ويرى قائمة كل الأعضاء المسجّلين.
- **العضو (Member):** يرى مشاريعه فقط؛ أي مشروع يُضاف أو يُعدَّل يذهب لحالة "قيد المراجعة" ولا يظهر على الموقع العام إلا بعد موافقة المسؤول. هذا مطبّق على مستوى السيرفر (وليس فقط الواجهة).

## قسم «الفريق على اللوحة» (Team Tactical Board)

قسم تفاعلي يعرض الفريق كمصفوفة أدوار مترابطة بدل بطاقات موظفين تقليدية، داخل `team-tactics/` ومعزول تمامًا عن بقية الموقع.

- **لا مواقع ثابتة للأعضاء:** التوزيع محسوب آليًا من `position` + `role` + درجة الخبرة عبر `formationEngine.js`. إضافة عضو جديد تعني إضافة كائن في `teamData.js` فقط — المحرك يجد له موقعًا ولا يحتاج أي إحداثيات.
- **4 تشكيلات جاهزة** (`متوازن / هندسي / إبداعي / شركة ناشئة`)، والإضافة بينها تنقّل بحركة Layout بدون إعادة تحميل.
- **خطوط الاتصال SVG ديناميكية:** تُعاد هندستها كل إطار أثناء التنقل، فتبقى ملتصقة بالأفاتار دائمًا. خطوط التعاون بين التخصصات لا تظهر إلا عند تركيز العضو.
- **لوحة تفاصيل جانبية** (Bottom sheet على الجوال) بدون مغادرة الصفحة، مع دعم كامل للوحة المفاتيح و ARIA.
- **يدعم `prefers-reduced-motion`**: يلغي التتابع والحركات ويعرض اللوحة جاهزة فورًا.
- **جاهز للربط بمصدر بيانات خارجي:** كل ما يلزم هو استبدال جسم `fetchTeam()` في `teamData.js` بنداء `fetch("/api/team")` أو Supabase — بدون أي تعديل على الواجهة.

## البنية (الملفات)

- `index.html` + `styles.css` + `script.js` + `i18n.js` + `portfolio.js` — الموقع العام (ثنائي اللغة عربي/إنجليزي)
- `admin/` — لوحة تسجيل الدخول/التسجيل + إدارة المشاريع (تختلف الواجهة حسب دور المستخدم)
- `server/` — خادم Express + PostgreSQL (`server/db.js`) + تكامل Supabase Storage (`server/storage.js`)
- `render.yaml` — إعداد جاهز للنشر السحابي على Render
- `uploads/` — **fallback محلي فقط** لصور المشاريع عند عدم ضبط متغيرات Supabase Storage؛ لا يُستخدم في الإنتاج
- `assets/` — الشعار، أنماط الجسيمات (شبكة نقاط متصلة/network)، صور الحالات الدراسية الافتراضية
- `team-tactics/` — قسم الفريق التفاعلي (لوحة تكتيكية + محرك التشكيلات)؛ معزول: ملفاته وCSS خاصته فقط، راجع `team-tactics/README.md`

## قاعدة البيانات

Postgres (عبر Supabase). الجداول (`users`, `projects`) تُنشأ تلقائيًا عند أول اتصال بقاعدة بيانات فارغة، وتُملأ ببيانات تجريبية أولية لثلاثة مشاريع وحساب مسؤول واحد. لا حاجة لتشغيل أي SQL يدويًا.

## الأمان

- كلمات المرور مشفّرة بـ bcrypt.
- المصادقة عبر JWT موقّع (صالح 8 ساعات) — مقاوم لحظر الكوكيز الطرف-ثالث في بيئات المعاينة المضمّنة (iframe).
- تحديد معدل محاولات تسجيل الدخول/التسجيل (10-8 محاولات كل 15 دقيقة لكل IP).
- كل نقاط الـ API الخاصة بالإدارة محمية بالتحقق من الهوية والدور (admin/member) على مستوى السيرفر.
- مفتاح `SUPABASE_SERVICE_ROLE_KEY` يُستخدم فقط من طرف السيرفر، ولا يُكشف أبدًا للمتصفح.
